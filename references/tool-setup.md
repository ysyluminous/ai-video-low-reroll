# 工具接入与选型

> 附录文件，配合 `SKILL.md` 第 0、1、8 节使用。

## 一、用到的模型和工具

| 东西 | 角色 | 干什么 |
|---|---|---|
| Claude（Claude Code） | 总导演 | 写故事和分镜、写所有提示词、调用其他模型、抽帧放大检查、写代码做后期 |
| Codex | 画师 | 画设定图、样帧、每个镜头的首尾帧 |
| Seedance（火山引擎方舟） | 动画师 | 把首尾帧变成几秒钟的视频 |
| ffmpeg | 工具 | 拼接、转场、调色、放大 |
| Python | 工具 | 色块草图、抽帧、批量处理和检查脚本 |

其他两个模型都接进导演，让导演去调用。这样全程只和导演沟通，不切窗口、不复制粘贴。

没有 Claude 时可以直接用 Codex 当导演：codex 也能干这些活，只是 Claude 更聪明、审美更高一些。

## 二、接入步骤

1. **Codex**：本机已装 Codex 即可。直接告诉导演「图片你去调用 Codex 生成」。
   调用方式：

   ```bash
   codex exec --skip-git-repo-check -s read-only -i 参考图.png - < 提示词.txt
   ```

   提示词开头固定写：

   ```
   Use your image generation tool to create exactly ONE image. Do not run shell commands.
   ```

   出图位置：`~/.codex/generated_images/<日志里的 session id>/`。

2. **Seedance**：去火山引擎注册账号，申请 API key。让导演自己写调用脚本，按照它的要求把 key 填进环境变量 `ARK_API_KEY`，剩下的事它负责。

   接口：

   ```
   POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks
   ```

   key 只在环境变量里读，**不要打印出来**。请求格式以火山方舟当前文档为准。

3. **ffmpeg / Python**：本机可用即可，导演用它们做后期和检查。

## 三、模型与价格

| 模型 | 720p 参考价 | 适用 |
|---|---|---|
| `doubao-seedance-2-5-260628` | 约 ¥1.5/秒 | 复杂镜头、最考验模型能力的镜头 |
| `doubao-seedance-2-0-mini-260615` | 约 ¥0.5/秒 | 常规镜头，预算紧时首选 |

- 价格以实际账单为准；2.5 约是 2.0 mini 的 3 倍。
- 不是特别复杂的镜头，mini 已经很够用。
- 预算紧就全程用 mini，把钱留给真正难的镜头。

### 两个模型的已知脾气

| 模型 | 现象 | 应对 |
|---|---|---|
| 2.5 | 写了「没有音乐」还是可能混进音乐 | 不用片段自带声音，音效后期另加 |
| 2.5 | 结尾几帧突然跳到尾帧样子 | 后期选一张没问题的画面，后面都停在这一张 |
| 2.5 | 第一帧特别锐 | 直接去掉这一帧 |
| 2.0 mini | 越到后面越暗、越冷 | 每条按它自己的首帧把颜色调回来 |
| 2.0 mini | 自带音效经常能直接用 | 先听一遍，能用就用，不能用再换 |

## 四、文件与额度规矩

- 所有文件放在**一个新的项目文件夹**里。
- 新版本存新文件，不覆盖、不删除旧文件；重拍的片段也留着，最后一起挑。
- Codex 额度用完就等恢复：不买额度，也不一次同时画太多张。
- 不充值、不买额度。接口返回欠费就停，先把已有片段粗剪出来给人看。

## 五、导演的能力边界

- 看不到真正的动态，也听不到声音。
- 没看过的、没听过的，必须明确说出来，不能默认没问题。
- 每一张图、每一段视频都要抽帧放大检查，而不是只看生成成功的提示。
