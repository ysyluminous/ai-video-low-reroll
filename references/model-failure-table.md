# 模型易犯错对照表与审核清单

> 附录文件，配合 `SKILL.md` 的第 5、6、7、8 节使用。

## 一、模型最容易犯的错 / 应该怎么写（20 条）

| # | 模型容易犯的错 | 应该怎么写 |
|---|---|---|
| 1 | 一群人同时做同一个动作 | 写清谁先谁后：「老爸第一个……过一两秒老奶奶才……小女孩最后……」；首帧也不要摆同一个姿势 |
| 2 | 本该风做的事，人自己动手做了（比如邮差用手掀开邮包） | 写清原因，再写「两只手从头到尾都没有碰邮包」 |
| 3 | 云、月亮、植物长出眼睛和嘴巴 | 不写「卡通云」，写「蓬松的灰白色积云，只有棉絮一样的纹理和阴影」，动作只写它怎么移动 |
| 4 | 人往反方向走 | 方向按画面写：「朝画面左边走，跨过左边的店门」 |
| 5 | 一句话有两种意思（写「窗户后面的老人」，结果车里冒出了人） | 写更具体：「左上角石头房子的窗口里」，再加「驾驶座一直空着」 |
| 6 | 东西的数量变了 | 把数量直接写出来：「只有一封黄信封，之后他怀里全是白信封」 |
| 7 | 写「不要怎么样」不管用（写了「壶嘴不出水」还是出水） | 改成正面的说法：「画面里一直只有首帧这几个人」 |
| 8 | 模型自己联想道具的用法（壶总是出水） | 干脆不让这个道具出现在有动作的镜头里 |
| 9 | 东西凭空出现 | 只用首帧里已经有的东西 |
| 10 | 东西突然飞走或瞬间移动 | 写清它是怎么动的：「顺着后脑勺往后一滑，接住，扣回头上」 |
| 11 | 雨、帽子、纹身拍着拍着就没了 | 首帧和尾帧都画上 |
| 12 | 闪电画得太写实 | 写「云里闪一下白光」，再把开头剪掉 |
| 13 | 一个镜头动作太多就乱 | 每个镜头只写一两个主要动作 |
| 14 | 动作的时间和写的不一样 | 写的时间只算大概，多留一点时间，后期再用剪辑和变速对上节拍 |
| 15 | 镜头推得没有写的那么明显 | 后期用代码再推一点 |
| 16 | 人的嘴自己在动 | 写明「人物不说话」，还动就用代码修 |
| 17 | 写了「没有音乐」还是混进了音乐（Seedance 2.5） | 片段自带的声音不用，后期另外加 |
| 18 | 结尾几帧突然跳到尾帧的样子（Seedance 2.5） | 后期选一张没问题的画面，后面都停在这一张 |
| 19 | 第一张画面特别锐（Seedance 2.5） | 直接把这一张去掉 |
| 20 | 视频越到后面越暗越冷（Seedance 2.0 mini） | 每条视频都按它自己的首帧把颜色调回来 |

## 二、首尾帧画完要逐条查（放大看）

1. 动作要用到的东西，首帧里必须有（否则会凭空冒出来）。
2. 别人的反应要提前摆好：一个镜头内切不出去，首帧里就要安排好位置和朝向。
3. 多人不能摆同一个姿势，否则会同时动。
4. 给动作留空间：东西要落到的地方、人的头顶都要留白。
5. 风往哪边吹要统一，不能围巾往左、床单往右。
6. 缩到手机大小看一遍，远处的人太小就改。
7. 放大看有没有多余的东西（多一只壶、多一条细线）。
8. 首尾帧叠在一起看有没有错位：不该变的地方必须一致，否则视频里会慢慢变色/变大。

## 三、提交视频前的审核（提示词见 `prompts.md#提交前审核`）

只读不改，只挑错。核对 5 项：

1. 提示词每句话和两张图对得上吗（位置、左右、颜色、人数、道具数量、衣服、表情）。
2. 两图机位、大小、背景一致吗。
3. 和设定图、配色规则、前后镜头对得上吗。
4. 动作现实吗，原因写了吗，手放在哪。
5. 模型可能在哪出错：同时动作、凭空出现、长脸、走反方向、歧义词。

只输出「通过 / 不通过」；不通过逐条列改法。

**真查出过的例子**：两张图杯子大小差 13%、帽檐一张有一张没有、左右写反。漏掉一个，就是一次按秒计费的重拍。

## 四、出问题后的修复顺序

按这个顺序试，能停在前一步就别花钱：

| 顺序 | 做法 | 成本 |
|---|---|---|
| 1 | 只出现在开头或结尾几帧 → 直接剪掉 | 几乎为零 |
| 2 | 嘴动、颜色偏、推镜不够、画面小错 → 让 AI 写代码修 | 几乎为零 |
| 3 | 修不了才重拍，**且必须先改提示词或首尾帧** | 按秒计费 |
| 4 | 重拍只拍这一镜，不推倒整支片 | 按秒计费 |
| 5 | 旧片段不删，新旧放一起挑 | 零 |

原样再拍一次，大概率还是同一个错。

## 五、成片复核（提示词见 `prompts.md#成片复核`）

新开一个 agent，只给成片、不给结论。要求它：全部解码，每镜多帧，切点前后各 3 帧；先讲看懂的故事；再逐镜查重复动作、道具数量、穿帮、突跳、颜色跳变、脸变形、字；明确写出查不了的（动态手感、声音）；每条写时间、帧号、问题，分「硬伤 / 小问题」。
